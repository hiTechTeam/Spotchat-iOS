# Spotchat: техническая основа

## Статус этапа 1

Отдельный репозиторий hiTechTeam/Spotchat-iOS с историей Bitchat. Исходный
интерфейс и поведение сохранены для проверки сборки. Это ещё не минимальное
приложение Spotchat: интернет-функции upstream пока присутствуют.

Исходная версия: permissionlesstech/bitchat,
`9b84b361225facd8e623f25d76f889d3dc54a879`.
`upstream` указывает на Bitchat; `origin` — на Spotchat-iOS.

## Важные зависимости

`BLEService` не является готовым независимым Swift-пакетом. Его конструктор
принимает `KeychainManagerProtocol`, `SecureIdentityStateManagerProtocol` и
`NostrIdentityBridge`. Кроме того, он использует общий протокол, модели,
шифрование, синхронизацию и хранение. Поэтому на старте сохраняем рабочее
дерево исходников и уменьшаем его после получения работающего обмена.

`ChatViewModelServiceBundle` сейчас создаёт `MessageRouter` с двумя транспортами:
`[meshService, nostrTransport]`. `ChatViewModelBootstrapper.configure()` запускает
также геоканалы, gateway и bridge. Удалить вкладки недостаточно: для офлайн-версии
нужно отключить соответствующий запуск, маршруты и сетевые сервисы.

`NostrIdentityBridge` участвует в локальной идентичности, поэтому нельзя просто
удалить всю папку Nostr. Аналогично P256K (`swift-secp256k1` 0.21.1) пока нужен
существующему графу зависимостей. Tor поставляется через локальный пакет Arti
с бинарным XCFramework; он не нужен целевому BLE-чату, но сохранён в baseline.

BLEService различает Debug и Release UUID. Два устройства для первого теста
должны использовать одну конфигурацию. Сейчас UUID унаследованы от Bitchat;
перед самостоятельным тестом Spotchat следует выделить собственный service UUID,
чтобы приложение не смешивалось с соседними пользователями Bitchat.

Доступность по mesh не доказывает физическое соседство: участник может быть
достижим через ретранслятор. Для списка «рядом» нужно определить политику прямой
связи и последнего подтверждённого контакта. Нельзя подменять её GPS-расстоянием
или мгновенно убирать человека из-за одного пропущенного пакета.

## Источники интерфейса

- Telescan-iOS (`../Telescan-iOS`, HEAD при исследовании
  `019fea820ffbcd31c11cec691e11e6db2f266b66`): собственные компоненты профиля и фото.
  Текущий профиль связан с `CodeViewModel`, а обнаружение разрешает профиль через
  API. Для Spotchat нужна локальная модель имени, описания и аватарки.
- Telegram-iOS: ориентир для списка, пузырей сообщений и поведения навигации.
  Код Telegram на этапе 1 не перенесён. Любой последующий перенос должен учитывать
  лицензию конкретных файлов и их зависимости.
- Утверждённые макеты: список людей рядом, собственный профиль в `.medium`,
  личный чат и карточка собеседника в `.medium`.
