# Этап 5 — переподключения, фон и подтверждения

## Изменения

- Отправленное сообщение при обрыве получает подпись «Ожидаем связь».
  Попытки передачи при отсутствии прямой связи не расходуются. После
  восстановления отправляется тот же ID; принимающая сторона подавляет дубли.
- Ожидание связи ограничено 120 секундами активного времени приложения.
  После истечения срока доступен ручной повтор с тем же ID.
- В непрерывном соединении сохраняются три попытки с интервалом 10 секунд.
  Галочка появляется только по подтверждению собеседника. Позднее настоящее
  подтверждение исправляет ошибку; локальный callback не отменяет прочтение.
- Таймеры доставки и опрос профилей приостанавливаются в фоне. Возврат даёт
  BLE/Noise свежий интервал ожидания подтверждения; час приостановки не
  превращает ожидающее сообщение в ошибку. Загрузка фото возобновляется
  с сохранённого смещения, если соединение и запрос сохранились.
- Подтверждение прочтения отправляется только для открытой переписки при
  активном приложении. Оно повторяется до трёх раз с интервалом 10 секунд,
  максимум 20 отправок за проход. Повторное открытие не рассылает всю историю
  без ограничений. Получение в фоне подтверждает доставку, сохраняя unread.
- При выключенном Bluetooth устаревшие снимки подключений не возвращают
  людей в список. Начальное состояние сцены учитывается до запуска Runtime.

## Автотесты

Первый прогон на iOS 18.5 Simulator: 16 успешных тестов `SpotchatRuntimeTests` и
`SpotchatProfileTests`. Добавлены проверки обрыва, ограниченного ожидания,
повтора с прежним ID, часовой приостановки, ограниченных read receipts,
устаревших снимков после выключения BLE и продолжения загрузки фото.
Финальная правка сохраняет общий лимит трёх попыток при частых
переподключениях; добавлен отдельный регрессионный тест этого случая.
Финальный прогон: **17 тестов прошли**, `TEST SUCCEEDED`.

## Физический прогон

DEBUG-режим `-SpotchatSelfTestStage5 -SpotchatSelfTestOpenChat` используется
только с явными `SpotchatSelfTestRun` и `SpotchatSelfTestName`. Он открывает
настоящую переписку только с другим устройством того же тестового запуска.
Профили временные, сообщения синтетические. Локальный файл команды
`Documents/spotchat-test-command.json` позволяет отправить маркированное
сообщение или остановить BLEService на 20 секунд. Сетевого интерфейса
управления нет. JSON-диагностика содержит session ID, реальные события
сцены, статусы сообщений, unread, подтверждения и переходы присутствия.

## Результаты на iPhone 11 и iPhone 14 Pro, 2026-09-10

Прогон `S510A`, JSON в `evidence/stage5/`:

| Сценарий | Наблюдение |
| --- | --- |
| Оба приложения открыты | Текст в обе стороны прочитан; аватары совпали по SHA-256 |
| iPhone 14 Pro в «Настройках» | Сообщение получено через 55 секунд после ухода в фон; у отправителя delivered, у получателя unread |
| Возврат 14 Pro | Тот же процесс, unread снят, отправителю пришёл read |
| iPhone 11 в «Настройках» | Сообщение получено через 56 секунд после ухода в фон; delivered без ложного read |
| Возврат 11 | Подтверждение read дошло до 14 Pro |
| Остановка/старт BLEService | Зафиксирован краткий разрыв и восстановление; новый текст после восстановления прочитан |
| Новый процесс на 14 Pro | Session ID изменился; 11 сохранил свой процесс. Новый текст прочитан, профиль и фото снова получены |

Данные автоматически сверены по ID сообщений, session ID, событиям сцены,
read/unread и хешам. Получение в фоне происходило при `appActive=false`;
read-sent для этих сообщений появился только после возврата.

Остановка BLEService не гарантирует отключение обеих физических ролей:
связь восстановилась ещё до запланированного запуска через 20 секунд.
Завершение процесса через devicectl также не эквивалентно пользовательскому
смахиванию из переключателя приложений: появился новый процесс, а прежний
JSON перестал обновляться. Этот промежуточный снимок не использован как
доказательство фоновой доставки или исчезновения человека. Для проверки
нового процесса сделан явный запуск с завершением предыдущего экземпляра.
Полное исчезновение после физического удаления телефона из радиуса в этом
прогоне не проверялось; фильтрация присутствия покрыта автоматическими тестами.

Настройки Wi-Fi и мобильной связи не переключались. Передача шла через
BLEService; Nostr/Tor/интернет-транспорт не создавались. Финальная сборка
для устройств прошла и установлена на оба телефона.

## Границы проверки

Используются существующие background modes central/peripheral и восстановление
Core Bluetooth в Bitchat. iOS может замедлять обнаружение в фоне, приостанавливать
или завершать процесс; непрерывная фоновая доставка не обещается.
[Документация Apple](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html).

История переписки и очередь ожидающих сообщений пока находятся в памяти
процесса. После его завершения они не восстанавливаются. Свой профиль и
кэш аватарок сохраняются. Эти изменения не добавляют дисковую историю.
